# 连接学校与电脑

## 学校登录失败

SSH 服务器登录密码、学校账号密码与 AI Bro 云同步密码分别管理。云同步设置必须填写部署同步服务时创建的账号密码。

学校账号与 AI Bro 同步账号彼此独立。学校账号仅用于轻新课堂，不用于设备同步。

课程助手中的“检查学校连接”只访问公开校时接口，不提交账号或签到。连接成功只能证明校时服务可达，不能证明登录认证可用。

- `LOGIN_REJECTED`：学校没有接受这次认证；提示包含可用的数字状态码。请先在官方轻新课堂验证同一类账号及对应密码，不要反复尝试。
- `LOGIN_INCOMPLETE`：学校报告成功，但身份或会话字段不完整。本次会话未保存，不应据此判断密码错误。
- `LOGIN_BAD_RESPONSE`：响应缺少预期的状态结构，需检查服务或接口兼容性。
- 账号连接后课表读取失败会单独显示，避免把课程查询失败误报为登录失败。

这些诊断不显示服务器原始响应、账号、密码或会话。反馈问题时只需提供错误提示，切勿发送密码。

## 手机与 Mac 同步

当前使用仓库内的独立自托管同步服务，不是 iCloud，也不是登录学校后自动同步。

1. 按 [云服务部署指南](../../cloud/README.md) 部署服务并创建个人账号。真实 iPhone 使用可访问的 HTTPS 服务。
2. Mac：设置 → 账号与云同步，填写服务地址、用户名、密码，确认合并并连接。
3. iPhone：设置 → 设备与同步，填写同一个服务地址与账号，确认合并后“连接并同步”。
4. 首次在两端各点一次“立即同步”，用一条测试随记核对双向修改。冲突通过页面选择保留版本。

项目、任务、笔记、随记、已保存对话和受管附件参与同步。日程进入 Mac 原生日程中心需要本轮配套 Mac 构建，见 [日程适配说明](DESKTOP_AGENDA_SYNC.md)。模型密钥、学校凭据和设备通知权限不跨设备同步。

`127.0.0.1:8899` 是移动页面预览，不是同步服务；`?demo=1` 演示工作区不允许连接真实同步账号。真实 iPhone 中的 `127.0.0.1` 是手机本身，不能用来访问 Mac。Mac 上仅通过 SSH 隧道开放的回环地址也不能直接在手机使用。

## 无域名的真实 iPhone：Tailscale 私有同步

Mac 可以保留已绑定的 `http://127.0.0.1:18787` SSH 隧道；让服务器上的 Tailscale Serve 将 HTTPS 转发到同一进程的 `http://127.0.0.1:8787`。两种地址访问的是同一个数据库，无需移动服务器数据，也无需让 Mac 持续开机。

1. 服务器加入自己的 Tailscale 网络，iPhone 安装 Tailscale、登录同一网络并连接。
2. 服务器执行 `tailscale serve --bg http://127.0.0.1:8787`。首次使用时按官方提示启用 HTTPS。只使用 Serve，不启用公网 Funnel。
3. 手机同步服务填 Serve 输出的 `https://<设备名>.<网络名>.ts.net`，不追加 `/v1`；账号和密码填写 Mac 上的 AI Bro 同步账号。
4. 先在手机 Safari 打开该地址加 `/v1/health`，应显示 `{"protocol":1}`；再在 AI Bro 连接并同步，用一条随记验证双向传递。

HTTPS 的首次证书申请可能需要短暂等待。没有加入 Tailscale 网络、VPN 未连接或服务器离线时，手机无法访问此入口。已绑定其他地址的旧手机工作区不能直接改地址；请保留该工作区，另行处理地址迁移，不要清空资料。

无管理员权限的 Linux 服务器可使用官方静态二进制和 `tailscaled --tun=userspace-networking`，以 systemd 用户服务运行；将状态目录设为 0700，CLI 使用该实例的 `--socket`。不要把 Tailscale 状态文件、登录凭据、学校会话或同步密码纳入源码、备份公开包或聊天记录。
